# TAAMs 경매 시세 분석


조회 대상 농산물(사용자 입력, 미확정): $item_name
아래 1단계 `search_auction_items` 로 반드시 품목 코드를 확인한 뒤 진행한다 — 코드는 추측하면 틀린다.
이름이 주어지지 않았다면 사용자에게 무엇을 볼지 먼저 묻는다.

개별 도구의 데이터 규칙은 각 도구의 설명이 정본이다. 이 프롬프트는 호출 순서·분기·결과 배치만 다룬다.

호출 순서
1. search_auction_items 로 품목 코드를 확인한다 — 코드는 숫자 조합이라 추측하면 틀린다.
2. 사용자가 특정 도매시장을 말했으면 search_auction_markets, 특정 산지를 말했으면 search_auction_origins 로 그 코드를 얻는다.
3. get_auction_price 로 낙찰단가를 조회한다.

분기
· 응답의 data_status 와 market_axis 를 **먼저** 읽는다. 결과가 비는 이유는 여러 가지이고 뜻이 서로 전혀 다르다 — 그 구분은 도구 설명이 정본이다. 전부 '데이터가 없다'로 뭉뚱그리지 말 것.
· 기간이 일부만 조회됐으면(partial) 받은 값을 '요청하신 기간의 결과'라고 말하지 않는다.

결과 조합·배치
· **등급 구성을 먼저 보고 답을 시작한다.** 등급을 합친 평균이 움직인 것은 시세가 움직인 것일 수도 있고, 나온 물건의 등급 구성이 바뀐 것일 수도 있다. 둘을 구분하지 않은 '시세가 올랐다/내렸다'는 틀린 문장이 될 수 있다.
· 일별 시계열은 선 그래프로 그리고, 등급 구성은 비중으로 따로 보여 준다.
· 도매시장을 지정했으면 '전국'이 아니라 그 시장의 값임을 문장에 남긴다.

말하지 말 것
· **국내 경매 낙찰가(원/kg)와 수입 통관 단가(USD/kg)를 비교·환산·합산하지 말 것.** 통화도 유통 단계도 다른 값이다. 나란히 보여 주는 것은 가능하지만 왜 다른 값인지를 먼저 밝힌다.
· 며칠치 등락으로 앞으로의 시세를 예측하지 말 것.

(참고) 도구가 등급 제한·한도 초과로 정책 응답을 돌려주면(예: error='grade_required') 그 message 를 그대로 전달할 것 — 오류로 재해석하지 않는다.
