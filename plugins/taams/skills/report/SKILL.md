# TAAMs 품목 분석 리포트


분석 대상 품목(사용자 입력, 미확정): $product_name
아래 1단계 `search_products` 로 반드시 정확한 한글 품목명을 확정한 뒤 진행한다.
품목명이 주어지지 않았다면 사용자에게 무엇을 볼지 먼저 묻는다.

개별 도구의 데이터 규칙(단가 계산 방식·필드 의미·인과 해석 금지 등)은 각 도구의 설명이 정본이다. 이 프롬프트는 여러 도구를 어떤 순서로 부르고 결과를 어떻게 배치할지만 다룬다.

호출 순서
1. search_products 로 사용자가 말한 품목의 정확한 한글 품목명을 확인한다.
2. get_product_price 로 단가·수입량을 조회한다.
3. get_origin_weather 로 그 품목의 산지 기상·작황 정보를 조회한다.
4. 사용자 질문이 요구할 때만 선택적으로 더한다 — 공급처(수출사)를 물으면 get_product_top_exporters, 국내 경쟁 수입사를 물으면 get_product_importers, 단가가 아니라 장기 물량·계절성이 궁금하면 get_product_trend. 세 도구는 서로 대체재이며 필수 순서가 아니다.

분기
· get_origin_weather 응답이 ambiguous=true 면 candidates 중 하나를 임의로 골라 계속 진행하지 말 것 — 후보를 사용자에게 제시하고 그 자리에서 멈춘다. 사용자가 하나를 고르면 그 product_type 값으로 다시 호출한다.
· get_product_price 응답의 price_eligible 이 'N' 이면 이 품목은 단가를 산정하지 않는 품목이다. current_avg 등 단가 수치를 인용하지 말고 unavailable_reason 을 그대로 안내한 뒤, 단가 없이도 유효한 3~4단계(산지·수출사·추이)로 넘어간다.
· get_origin_weather 응답의 layer 가 1~2 면 산지 관측이 없는 품목이다 — 있는 층(통관 실적·거래시기, 또는 + 문헌 기후 기준)까지만 답하고, 3~4층에서만 나오는 관측·임계 판정 내용을 지어내지 않는다.

결과 조합·배치
· 사용자가 먼저 물은 것(대개 단가)을 가장 먼저 답하고, 산지 기상은 참고로 덧붙이는 사실로 뒤에 놓는다 — 먼저 놓으면 그것이 원인처럼 읽힌다.
· 단가·수입량·물량 시계열은 각 도구 설명의 차트 지시를 그대로 따른다(이 프롬프트가 차트 규칙을 새로 정하지 않는다).
· 산지 기상은 응답의 alerts/routine/safe_margin 세 갈래를 그대로 옮겨 쓴다 — 세 갈래를 합쳐 하나의 요약 문장으로 재구성하지 않는다(갈래를 섞으면 일상적인 값도 경고로 읽힌다).

말하지 말 것
· 여러 도구의 결과를 한 리포트로 합칠 때, 산지 기상과 단가·수입량을 인과로 엮지 말 것('산지가 더워서 값이 올랐다', '수온이 올라 물량이 줄고 있다' 같은 문장 금지). 세 사실은 같은 기간에 나란히 있었을 뿐이다 — get_origin_weather 자체의 목적도 '기후↔단가 연관 제시'가 아니라 '조회 품목의 상세정보 제공'이다.
· 단가와 수입량을 서로 인과로 연결하지 말 것. get_product_price 응답 자체에 이미 이 지시가 있다 — 여러 도구를 하나의 서사로 합치는 과정에서 이 지시가 흐려지지 않게 유지한다.

(참고) 도구가 등급 제한·한도 초과로 정책 응답을 돌려주면(예: error='grade_required') 그 message 를 그대로 전달할 것 — 오류로 재해석하지 않는다.
